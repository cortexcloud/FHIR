LinuxForHealth FHIR Parsson remediation checklist

Linear: CTXN-8876 · Parent: CTXN-8816 · Updated: 18 Sep 2026

1. Security decision

DependencyCurrentTargetReason
Server modulesParsson jakarta.json 1.1.11.1.9แก้ CVE-2023-7272 และรวม default JSON input limit ที่เพิ่มใน 1.1.8 สำหรับ CVE-2026-9563

Critical finding เกิดจาก JSON ที่ซ้อนลึกมากทำให้ Java stack overflow และ service ล่มได้. Ingress body-size limit ลด payload ขนาดใหญ่ แต่ไม่ป้องกัน payload ขนาดเล็กที่ซ้อนลึก จึงต้อง patch parser โดยตรง.

2. Why LinuxForHealth was selected

หลักฐานใน deployment commit fb2ce61b1c วันที่ 13 Oct 2024 ระบุชัดว่าเพิ่ม LinuxForHealth FHIR R4 เพราะใช้ pure PostgreSQL ที่รองรับ UTF-8 search. HAPI ที่ใช้อยู่ก่อนหน้าเป็น custom HAPI 6.10.x พร้อม Elasticsearch.

จาก source ปัจจุบัน HAPI ไม่ได้ลบอักษรไทยระหว่าง normalize และมี Unicode tests บางภาษา แต่ upstream ไม่มี Thai-specific search regression test. จึงยังสรุปไม่ได้ว่า HAPI แก้ use case ของทีมแล้วโดยไม่ทดสอบกับ PostgreSQL/Elasticsearch configuration จริง.

HAPI re-evaluation contract tests

  • สร้าง Patient ที่มีชื่อไทยทั้งอักษรฐาน สระ วรรณยุกต์ และชื่อที่ normalize เป็น Unicode คนละรูปแบบ.
  • ทดสอบ name, given, family แบบ startsWith, :exact และ :contains.
  • ทดสอบ full-name splitting แบบเดียวกับ new-demographic-api.
  • ทดสอบ sort, pagination และผลลัพธ์เมื่อมีชื่อไทย/อังกฤษปะปน.
  • ทดสอบ read-after-write ทันทีและหลัง Elasticsearch refresh.
  • รัน matrix ทั้ง PostgreSQL-only และ Elasticsearch-enabled; เปรียบเทียบกับ LinuxForHealth production behavior.

3. Fork build and release

  • Merge dependency PR หลัง Maven tests และ dependency resolution ผ่าน.
  • กำหนด immutable internal image tag; ห้าม deploy latest.
  • ปรับ/ยืนยัน fork release pipeline ให้ publish ไป registry ของ Cortex ไม่ใช่ ghcr.io/linuxforhealth.
  • Build server และ schematool images จาก commit เดียวกัน แล้วสแกน image ด้วย Trivy.
  • สร้าง deployment PR แยกเพื่อเปลี่ยน server/schematool image tags หลัง images publish สำเร็จ.

4. Runtime verification

  • Smoke test readiness/liveness, OAuth/JWT และ database connectivity.
  • POST/PUT representative FHIR resources และอ่านกลับโดยไม่เปลี่ยนข้อมูลภาษาไทย.
  • รัน Thai-name search matrix ผ่าน new-demographic-api.
  • ส่ง deeply nested JSON ที่ระดับปลอดภัยและยืนยัน parser ปฏิเสธ input โดย process ไม่ล่ม.
  • ส่ง oversized JSON และยืนยัน Parsson input limit/ingress limit ทำงานตามที่ออกแบบ.
  • เฝ้าระวัง 4xx/5xx, CPU, memory, restart และ database query latency หลัง rollout.
